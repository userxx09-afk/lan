    App catalog

    Installed programs are matched to the public winget catalog, downloaded once a day from Microsoft, to show which ones are behind. Rules below override the matching: ignore a program, map it to the right package, or set the version you want instead of the latest.

    Sign-in

    Let members of one AD group sign in with their own AD accounts. Actions are then audited under each person's name. After the first successful AD sign-in, the local admin account turns off. If AD sign-in ever stops working, delete the file shown below on the server to turn the local admin back on.

    NetInventory Agent (optional)

    For laptops and PCs that WinRM can't reach. A tiny scheduled task (as LOCAL SERVICE) sends a signed heartbeat every 5 minutes and the inventory once a day or when you click Rescan. It only connects out to this server over HTTPS, never listens, checks this server's certificate fingerprint, and never runs anything the server sends.

    How to stop the browser warning

    Trust this certificate on your PCs (quickest). Download it below, then in Group Policy Management edit a GPO linked to your computers: Computer Configuration > Policies > Windows Settings > Security Settings > Public Key Policies > Trusted Root Certification Authorities > Import, and pick NetInventory.cer. PCs trust it after their next policy refresh (gpupdate).

    Or use a certificate from your AD Certificate Services. Click Create request for AD CS to download NetInventory.req (the key stays on this server), then on any domain PC run certreq -submit -attrib "CertificateTemplate:WebServer" NetInventory.req NetInventory.cer (or paste the request into your CA's /certsrv page), and install the .cer it returns with Install certificate. Domain PCs already trust your CA, so no GPO is needed.

    Or upload a .pfx exported with its private key from any CA.

    Credentials

    Windows accounts are used for AD (LDAP) and for WinRM to PCs and DCs. SNMP v2c/v3 credentials are used for switches and routers. Secrets are encrypted on the server and never shown again.

    What to scan

    Add an AD domain, an OU of computers or users, or an IP range of network gear and PCs. Each target uses the credentials you pick, tried in order.

    Scanning exclusions

    Every scan (AD import, WinRM, SNMP and the WinRM port sweep) skips matching IP addresses, host names, AD OUs and MAC addresses. Windows events that match a Windows event exclusion aren't stored, so they never show up in reports or alerts. Event sources match loosely: DCOM and Microsoft-Windows-DistributedCOM are the same.

    Scan schedule

    Each job scans some of your targets (an OU, a domain, an IP range, or all of them) on its own schedule, for example one OU every 30 minutes and the rest once a day at night. A job never overlaps itself: if its last run is still going, the next one waits. Exclusions apply to every job. See what is scanning now.

    The up check (ping, then a TCP knock on 445/135/3389/5985) drives the green/red dot next to each PC. It is very light: one packet or connection per PC. 0 turns it off.

    More than one job at once finishes sooner but puts more load on the network, the DCs and this server. Jobs over the limit wait their turn.

    DameWare Mini Remote Control

    The Remote button opens dameware:// links. Each technician PC needs the NetInventory DameWare launcher (an installer option, or deploy dameware-handler.reg and Open-DameWare.ps1 by GPO). Extra DWRCC switches and a custom DWRCC.exe path are set per PC in the registry, not here, so a link can never pass arbitrary arguments.
